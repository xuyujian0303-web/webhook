# 企业微信销售推送机器人 Windows Server 部署设计

## 目标

在 Windows Server 内网环境中，将企业微信销售推送机器人部署为可长期运行、可自动恢复的服务。管理员通过内网网页维护规则、消息模板和运行参数；扫描服务持续读取 SQL Server 数据并发送企业微信消息。

## 已确认约束

- 服务器操作系统为 Windows Server。
- 后台网页仅允许公司内网访问，不开放公网。
- 可以安装 NSSM。
- 服务使用服务器本机专用低权限账号 `./svc-wecom-bot`，不使用个人账号或管理员账号。
- 商品图片由 SQL Server 返回内网 URL，正式环境不启动 `serve-images`。

## 方案比较

### 方案一：Python + Waitress + NSSM（采用）

服务器安装 Python、项目依赖、SQL Server ODBC 驱动和 NSSM。网页与扫描各自注册为 Windows 服务。NSSM 负责开机启动和异常重启，Waitress 负责承载网页 HTTP 请求。

优点是日志、故障恢复、更新和排错明确；ODBC 驱动和数据库连接仍由系统统一管理。缺点是服务器需要保留 Python 运行环境。

### 方案二：PyInstaller EXE + NSSM

程序可包装成单个 EXE，但仍需安装 ODBC 驱动、配置服务守护和处理日志。升级、依赖排错和安全补丁更复杂。因此不作为首次正式部署方案；可在稳定运行后按需要提供。

### 方案三：Windows 任务计划程序

可在开机时启动命令，但服务恢复、状态查看和日志处理不如 NSSM，不能作为正式推送进程的守护方式。

## 运行架构

```text
内网浏览器
    |
    | HTTP，仅允许公司内网网段
    v
WeComSalesBotWeb（Waitress + Flask）
    |                    |
    |                    +-- 后台业务数据库：用户、规则、模板、运行配置、推送记录
    |
    +-- 配置保存

WeComSalesBotScheduler（Python schedule）
    |                    |
    |                    +-- 每轮读取后台业务数据库：规则、当前模板、运行配置
    |
    +-- SQL Server：读取销售订单和商品图片 URL
    |
    +-- 企业微信 Webhook：发送 markdown_v2 消息
```

两个服务必须独立：网页进程重启不应停止扫描，扫描异常重启不应影响管理员编辑配置。

## 服务与配置

### `WeComSalesBotWeb`

- 启动目标：项目 CLI 的 `run-server`，改为使用 Waitress 监听 `backend.host` 和 `backend.port`。
- 监听地址：服务器指定内网 IP；禁止配置为 `0.0.0.0`，除非防火墙规则已严格限定来源网段。
- 外部访问：`http://<服务器内网IP>:<后台端口>/login`。
- 防火墙：仅允许公司内网网段访问后台端口。

### `WeComSalesBotScheduler`

- 启动目标：项目 CLI 的 `schedule`。
- 每一轮扫描前重新从后台业务数据库读取规则、当前模板和运行配置。
- 扫描服务全天按扫描间隔读取 SQL Server 并匹配规则；每日推送时段外不调用企业微信 webhook，也不标记订单为已推送。
- 网页保存规则、模板、扫描间隔、每条消息图片数、消息发送间隔或每日推送时段后，下一扫描周期生效，无需重启此服务。
- `datasource.local.yaml` 在扫描服务启动时加载；IT 修改 SQL Server 的连接、表名或字段映射后，必须重启此服务。
- 仅在企业微信 webhook 成功后才记录订单为已推送。非推送时段或发送失败的订单保留未推送状态，在后续允许时段自动补推。
- 不以“上次扫描时间”排除未推送订单；该策略保证时段外产生的订单不会被永久遗漏。推送状态文件必须落在持久化数据目录，不能随代码发布覆盖。

## 时间规则与网页填写说明

### 订单日期范围（新建规则）

订单日期范围是该规则的强制时间闸门，始终与金额、门店、款号、品牌、品类等条件取交集，不受“任一满足 / 全部满足”影响。

- 开始日期字段：可留空；格式为 `YYYY-MM-DD`，例如 `2026-08-24`。
- 结束日期字段：可留空；格式为 `YYYY-MM-DD`，例如 `2026-08-31`，当天按 `23:59:59` 包含。
- 仅填写开始日期：处理该日期及以后的订单。
- 仅填写结束日期：处理该日期及以前的订单。
- 同时填写：仅处理闭区间内的订单。
- 两者都留空：开始下限取扫描服务本次启动当天的 `00:00:00`，结束日期不限。这可避免首次启动或服务重启后推送长期历史订单。
- 结束日期早于开始日期：网页阻止保存并提示错误。

新建规则页面中每一个筛选项都必须提供格式与示例提示：金额填写数字，例如 `10000`；多值字段以英文逗号分隔，例如 `G621,G622` 或 `PA17047BNY0,PA17048BNY0`；日期按上述格式填写。

### 每日推送时段（运行配置）

每日推送时段不是规则条件，而是整个扫描服务的发送控制参数。

- 开始时间和结束时间格式均为 `HH:MM`，例如 `10:00` 和 `22:00`。
- 默认值为 `10:00–22:00`。
- 扫描服务全天持续扫描 SQL Server；仅在当前时间落入该时段时，才允许调用企业微信 webhook。
- 时段外命中的订单不标记已推送；进入下一个允许时段后自动补推，前提是订单仍满足对应规则的订单日期范围和其他条件。
- 结束时间早于开始时间的跨午夜时段不在本次范围内，网页应提示改为同一自然日范围。
## 目录与权限

正式部署将代码、配置和可写数据分开：

```text
C:\WeComSalesBot\app\        程序代码和虚拟环境，只读
C:\WeComSalesBot\config\     主配置、SQL 数据源映射配置，仅服务账号和 IT 管理员可读
C:\WeComSalesBot\data\       推送去重状态等持久化运行数据，服务账号可写
C:\WeComSalesBot\logs\       网页与扫描服务日志，服务账号可写
C:\Tools\nssm\               NSSM 可执行文件
```

`./svc-wecom-bot` 的最小权限：

- `app` 目录：读取和执行。
- `config` 目录：读取；仅 IT 管理员可修改。
- `data`、`logs` 目录：读取、创建和修改。
- 机器人后台业务数据库：仅限机器人自己的账号、规则、模板、运行配置、推送记录等表具有读写权限；不得与销售业务表混用。
- 销售 SQL Server 数据源：仅授予 `SELECT` 读取权限；明确拒绝 `INSERT`、`UPDATE`、`DELETE`、建表和改表权限。
- 企业微信 webhook：允许经服务器网络出口访问。

服务账号不授予本地管理员权限，不使用交互式个人账号。

## 安全与故障处理

- 配置文件含 webhook、数据库连接信息和后台初始密码，不提交代码库，不通过网页回显。
- 服务恢复策略：首次、第二次及后续故障均自动重启；延迟由 NSSM 配置，避免快速循环重启。
- 两项服务标准输出与错误输出分别写入 `logs`，保留用于排错。
- 部署前先使用 `run-once` 配合受控测试订单验证 SQL Server 和 webhook；未经确认不得对历史订单执行真实全量扫描。
- Windows 防火墙只开放后台端口给公司内网；SQL Server 与企业微信连接按现有网络策略放行。

## 安装、更新与验证

实现阶段将提供以下可复制执行的 PowerShell 脚本和交接文档：

- `scripts/deployment/start-web.ps1`：启动网页服务进程。
- `scripts/deployment/start-scheduler.ps1`：启动扫描进程。
- `scripts/deployment/install-services.ps1`：注册或更新两个 NSSM 服务。
- `scripts/deployment/uninstall-services.ps1`：停止并移除两个 NSSM 服务。
- `scripts/deployment/test-deployment.ps1`：检查配置、服务状态和网页连通性，不触发真实推送。
- `docs/deployment/windows-server-it-handoff-zh.md`：IT 安装、权限、防火墙、配置更新、故障排查和回滚说明。

更新顺序为：备份 `config`、`data` 和后台业务数据库，停止两个服务，替换 `app` 代码与依赖，执行验证，启动网页服务和扫描服务。配置与运行状态目录不随代码发布替换。

## 测试范围

- 自动化测试覆盖生产网页启动入口与部署配置校验。
- 本地验证两个脚本可启动对应进程，且可写入独立日志。
- 服务安装脚本以 `-WhatIf` 或显式测试模式验证参数构造，不自动注册到开发机。
- 正式服务器验收：网页登录、模板保存、规则保存、运行配置保存、下一扫描周期读取新配置、时段外订单不推送且时段开始后补推、日期范围拦截历史订单、NSSM 重启恢复、内网访问限制。

## 非目标

- 本次不打包 EXE。
- 本次不开放公网访问，不配置反向代理或 TLS 终止。
- 本次不改变 SQL Server 的表结构或字段映射逻辑。
- 本次不执行真实历史订单批量推送。
